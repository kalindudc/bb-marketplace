Hand a goal to a lead agent and keep the decisions. Tavern's Keeper scouts with Rangers, proposes a quest map for your approval, and delegates work to builders (Smiths) and an independent checker (Warden) while you steer from one thread instead of carrying messages between agents.

## Follow and steer the work

The Common room brings together what needs you, live quests, side quests, solos, and a summary of what changed since your last visit. Each quest page shows its map, road through the phases, party, Notebook, standing rules, decisions, spend budget, and event history. Open a member's report in the side panel, answer asks in place, and read the returned tale for verified results, open pull requests, credits, and work left for you.

Five classes separate leading (Keeper), scouting (Ranger), building (Smith), checking (Warden), and bounded side work (Wanderer); customize classes from the Classes page or Markdown override files. Characters appear as animated pixel-art sprites above the composer with seeded avatars you can roll and customize; characters add presentation only, never permissions or expertise. A Warden check is labelled as same-family whenever an independent model family cannot be established.

Long-running work scales without losing context: refresh a Keeper onto a fresh thread while carrying its charge and open asks, or hire a child Keeper lead for a greenlit waypoint under shared chain depth, seat, and spend limits.

## A journal in every thread

Every bb thread gets a Journal checklist with steps, blockers, evidence, assigned Warden verification, and grouped Undo. Linked work requires evidence, and only its assigned Warden can verify or reject it. Journal reminders never start agent turns, and Keepers' board quests stay separate from personal thread checklists.

## Guardrails, machines and control

Explicit plan approval is the default. Standing rules stay local to one Keeper unless you make them global. You can set a spend budget on a quest, delegate chosen consequential kinds per quest with Undo, or pause work cleanly with Closing time and Stop all.

Scope presets constrain each class. On macOS, local Pi sessions use a pre-execution guard and OS bash sandbox; consequential shell acts, cluster writes, and sends as you are guarded separately, and cluster writes always require your approval plus immediate confirmation. Claude Code and Codex require an explicit detection-only exception that notices violations without preventing them before execution.

Machine rules in Settings let you place working members on dedicated machines through bb's providers, choose per-class models per rule, and open draft pull requests from home via GitHub or custom forge profiles. Settings also offers guided setup proposals, TOML export and import, Insights with Burn cost data when installed, and private server-local backups from the page or `bb tavern`.

## Current limits

Pre-execution prevention applies to guarded local Pi sessions; other providers and placed remote members run detection-only under Tavern. Machine placement runs only rules requesting a new machine with a dedicated checkout. Quest spend budgets count only spend Tavern can measure, and already-admitted work can exceed the cap. In addition, bb currently does not distinguish human clicks from unmarked client calls.
